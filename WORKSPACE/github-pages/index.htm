// Der Loop

tick() — Das Herzstück

L1 Identity & Soul berechnen compute_soul(base, agenda, accounts, social, decentral)
L4 JIT Context Loading (3-Stage) always ~3k · agenda ~8k · query on-demand ~5k
L3 Planen planner(soul_t, hooks, memory, guidelines)
L3 Handeln — Tool oder Skill executor(plan) · skill_executor(plan.skill, context)
L3 Beobachten observer(results, diary, guidelines)
RFL Reflexion & Revision reflect(assessment) → planner.revise() → zweiter Versuch
L2 LTM & Guidelines aktualisieren observer.extract_lessons() → GUIDELINES/ · ltm_update()
core/runtime.py — async def tick()
# L1 — Identity & Soul
soul_t = compute_soul(base, agenda, accounts, social, decentral)

# L4 — JIT Context Loading (3-Stage)
registry.execute("load_context_always", {})
registry.execute("load_context_agenda", {agenda})

# L3 — Denken
hooks = load("identity/hook.md")
guidelines = registry.execute("read_guidelines", {task_type})
plan = planner(soul_t, hooks, memory, guidelines)

# L3 — Handeln (Tool oder Skill)
if plan.type == "skill":
  results = skill_executor.execute(plan.skill, context)
else:
  results = registry.execute(plan.tool, plan.params)

# L3 — Beobachten
assessment = observer(results, diary, guidelines)

# RFL — Reflexion & Selbstkorrektur
if assessment.needs_revision:
  reflection = reflect(assessment, results, plan)
  plan = planner.revise(soul_t, reflection)
  results = executor(plan) # Zweiter Versuch

# L2 — Procedural Memory + LTM
observer.extract_lessons(results) # → GUIDELINES/
ltm_update(results, assessment)
// Working System — AAMS v1.3.0

Acht Memory-Schichten. Epistemische Hygiene.

PROJECT/
Strategic Memory
Woran arbeite ich?Scope · Goals · Milestones
_active.yaml → max 1 aktiv
WORKPAPER/
Working Memory
Was tue ich jetzt?Eine Datei pro Session
open → work → close → archived
WHITEPAPER/
Semantic Memory (stabil)
Wie ist das System aufgebaut?CORE · IDENTITY · WORKING · TOOLS
MEMORY / LTM
Semantic Memory (gelernt)
Was haben wir gelernt?ltm-index.md · optional ChromaDB
ingestiert aus geschlossenen WPs
DIARY/
Temporal Index
Wann wurde was angefasst?Pointer-only · max 3 Einträge/Tag
YYYY-MM.md monatliche Dateien
GUIDELINES/
Procedural Memory
Wie arbeite ich am besten?Observer extrahiert Lektionen
wächst mit jeder Session
SCIENCE/
Epistemisch
Stimmt das? Wo stehen wir?research · validate · hypothesize
Eigene Lösung vs. State-of-the-Art
TOOLS/skills/
Skill-Orchestrierung — L5
Wie kombiniere ich Tools?Markdown + YAML Workflows
multi-step Prozesse als Skill

Wissenskette (strikt): Workpaper → Whitepaper → LTM — flüchtige Ideen werden erst Architektur, dann Langzeitgedächtnis. Whitepaper > Guideline bei Konflikt.

// Quick Start

In fünf Schritten zum laufenden Agenten.

01
Repo klonen
git clone https://github.com/DEVmatrose/MantisClaw cd MantisClaw
02
Virtualenv
python -m venv .venv source .venv/bin/activate pip install -r requirements.txt
03
Konfiguration
cp config/.env.example .env

LLM_BACKEND=lmstudio (default) oder ollama
Optional: OPENAI_API_KEY, ANTHROPIC_API_KEY

04
Identität einrichten
cp identity/base.md.example identity/base.md cp identity/agenda.md.example identity/agenda.md

Optional: account, social, decentral, hook

05
LLM & Agent starten
# LM Studio: Server auf :1234 # oder Ollama: ollama serve ollama run qwen3-coder python -m core.runtime
// Integration

Standalone oder Teil von Mantis-OS.

Standalone
MantisClaw
Gehirn + Identität + AAMS Body. Einzelnes Repo, eigenständig lauffähig. Local-first, kein Cloud-Zwang. Der Code ist identisch mit MantisClaw in Mantis-OS.
+
Optional
MantisNostr
Mesh-Netzwerk Layer. L6 Network. Agenten kommunizieren über das Nostr-Protokoll in einem dezentralen Mesh.
=
Vollständiger Knoten
Mantis-OS
Autonomes Agenten-Betriebssystem. MantisClaw als Gehirn, MantisNostr als Nervensystem. Nur die Integration unterscheidet sich.
